# Идея: Ш.А.Т.А.Л.К.Е.Р.

Режим работы: **писать в Cursor, код не читать, только играть и проверять ощущения.**

Это не настоящая онлайн-игра и не ремейк чужой франшизы. Это **максимально дешёвая браузерная имитация сетевого шаталкера** в литературном жанре аномальной зоны.

Сначала — **одиночный клиент с фейковым онлайном**. Настоящий сервер — только потом, если захочется.

**Главная задача: производительность.** Стабильные ~60 FPS важнее новых систем. Правила — в [performance.md](./performance.md).

> **Стек:** Vite + TypeScript + Babylon.js + React (UI) + Zustand (состояние). Без Tailwind — один лёгкий CSS под КПК.  
> **Форма:** не настоящее MMO, а мини-песочница с ботами, заказами, автобоем, автопоиском и рацией.  
> **Мир:** Периметр. Ты — шаталкер. Название игры — **Ш.А.Т.А.Л.К.Е.Р.**

---

## 0. Жанр и имена

Литературный ориентир: закрытая аномальная территория, артефакты, мутанты, лагеря добытчиков, туман, ржавчина, заказы у барыги. Не копировать чужие локации, фракции, персонажей и торговые марки.

В коде, UI и текстах игры:

- название — **Ш.А.Т.А.Л.К.Е.Р.**;
- человек, который ходит в зону — **шаталкер**;
- аномальная территория — **Периметр**;
- первый лагерь — **Застава «Насыпь»**;
- квестодатель — **Барыга Кефир**;
- первый мутант — **хряк**;
- HUD — как грязный КПК, не «золотая китайская рамка».

Расшифровка (флор игры, не канон вселенной):

> **Ш**атающиеся **А**вантюристы, **Т**рофейщики **А**номалий, **Л**азутчики, **К**ладоискатели, **Е**геря, **Р**ейдеры.

Игрок так себя не называет. Так дразнят на заставе.

## 1. Почему такой стек

### Движок / 3D: Babylon.js

Для 3D-игры в браузере даёт много готового: сцена, камера, свет, меши, материалы, анимации, физика по желанию, GUI, загрузка моделей, инспектор сцены, нормальный TypeScript.

Для вайбкодинга движок должен быть **самодостаточным**. Babylon удобнее голого Three.js, где всё собирается вручную из библиотек.

### Интерфейс: React

У шаталкера много UI, как у дешёвой онлайн-игры, только в шкуре КПК:

- рамка игрока и цели;
- панель действий;
- трекер заказа;
- инвентарь;
- диалоги;
- рация / чат;
- миникарта;
- всплывающие цифры урона;
- меню настроек;
- кнопка «Авто».

Делать это внутри 3D-канваса — боль.

> 3D-мир — в Babylon.  
> UI — в обычном DOM через React, стилизованный под КПК.  
> Стили — один (или несколько) обычных `.css`. Без Tailwind, без CSS-in-JS, без UI-китов. Игра должна оставаться лёгкой.  
> Кадр принадлежит Babylon. React и Zustand не обновлять 60 раз в секунду.

### Состояние: Zustand

Простой глобальный стор:

- HP / выносливость шаталкера;
- ранг и опыт;
- цель;
- заказы;
- инвентарь;
- активные окна;
- рация;
- состояние боя.

Почему Zustand: простой, мало boilerplate, хорошо дружит с React, удобно обновлять из игрового цикла.

### Сборка: Vite

Быстрый запуск, горячая перезагрузка, простая структура, нормальная работа в браузере, минимум магии.

### Почему не Unity / Unreal / Godot

- **Unity** — сцены и префабы часто скрыты, ссылки в инспекторе ломаются, ИИ не кликает по редактору, веб-сборки тяжёлые.
- **Unreal** — слишком тяжёлый, не для лёгкой браузерной игры и вайбкодинга.
- **Godot** — хороший, но сцены, экспорт в веб и версии хуже ложатся на Cursor. Для «проверил в браузере» веб-стек проще.

## 2. Почему не начинать с настоящего онлайна

Настоящая сетевая игра — это сервер, БД, авторизация, синхронизация, античит, экономика, модерация чата, группировки, инстансы, шарды, нагрузка, админка, патчинг.

Если код не читается, а только играется — настоящий онлайн слишком рискованный.

Правильный путь:

> Сначала «иллюзия Периметра»: боты-шаталкеры, локальный лагерь, локальные заказы, локальная рация.  
> Потом Gin + Postgres + WebSocket, см. [backend.md](./backend.md) и [plan.md](./plan.md).

## 4. Механика

### Вид

- Третье лицо, камера позади персонажа.
- Камера вращается мышью или следует автоматически.
- Персонаж — оливковая капсула или простая моделька.
- Мутанты — ржаво-красные капсулы (хряки).
- NPC — грязно-жёлтый цилиндр (барыга).
- Маркер заказа — тускло-жёлтый конус.

Сначала не нужны красивые модели. Сначала нужен цикл.

### Управление

| Клавиша / действие | Что делает |
| --- | --- |
| `WASD` | Движение |
| Мышь | Камера |
| Клик по земле | Идти в точку |
| `Tab` | Ближайшая цель |
| `1` | Обычная атака |
| `2` | Приём / навык |
| `F` | Разговор с NPC |
| `I` | Инвентарь (КПК) |
| `M` | Карта |
| `Enter` | Рация |
| Кнопка **Авто** | Автобой / автопуть по заказу |

Кнопка **Авто** сама ищет цель заказа, идёт, бьёт, возвращается к барыге, сдаёт заказ, берёт следующий. Даже примитивная логика даёт нужный вайб дешёвого онлайна в Периметре.

### Бой

Не шутер с прицеливанием, а **таб-таргет** (проще для ИИ и ближе к дешёвой онлайн-игре):

- выбрал мутанта;
- нажал атаку;
- если цель в радиусе — урон;
- над мутантом всплывает цифра;
- мутант отвечает;
- при смерти — опыт и лут.

### Автобой

1. Найти ближайшего живого мутанта нужного типа.
2. Выбрать его в цель.
3. Подойти.
4. Атаковать.
5. Если умер — найти следующего.
6. Если заказ выполнен — идти к NPC.
7. Сдать заказ.

Сначала без поиска пути: идти по прямой. Если застрял — телепорт к цели через дебаг-кнопку.

### Фейковый онлайн

5–10 фейковых шаталкеров: ходят по точкам, иногда бьют хряков, иногда пишут в рацию.

Позывные: `Ржавый`, `Окурок`, `Плут`, `Газик`, `Кочегар`, `Лом`.

Примеры сообщений:

```text
[Периметр] Ржавый: Кто на хряков? Пачка патронов в долю.
[Периметр] Окурок: Аптечки дёшево, без вопросов.
[Система] Шаталкер Лом повысил ранг.
[Система] На севере зафиксирован аномальный шторм.
```

Это даёт больше «онлайнового» ощущения, чем реальный сервер на первом этапе.

## 6. Чего не делать в первой версии

Не делать сразу:

- настоящую авторизацию, БД, регистрацию;
- PvP, экономику, аукцион, торговлю между игроками;
- группировки, войны за лагеря, полёты;
- огромный открытый Периметр;
- сложный инвентарь с обвесом, крафт, технику, компаньонов;
- сложные навыки, аномалии как полноценную физику, радиацию как симуляцию;
- серверную архитектуру;
- чужие имена локаций, фракций и персонажей из коммерческих игр.

Это убивает проект на этапе вайбкодинга.

Первый этап: **одиночная вылазка, которая выглядит как общий Периметр.**

Внутри: один игрок, локальный лагерь, локальные мутанты, сохранение в `localStorage`, имитация рации, другие шаталкеры — боты, «сетевые» события — локальные таймеры.

### Связь Babylon и React

- Babylon — 3D-мир Периметра.
- React — КПК и остальной интерфейс.
- Zustand — состояние.
- Игра пишет в стор, UI читает стор.
- Кнопки UI вызывают команды игры.

```ts
type GameApi = {
  moveToPoint: (x: number, z: number) => void;
  attackTarget: () => void;
  useSkill: (skillId: string) => void;
  interact: () => void;
  toggleAuto: () => void;
  spawnMonster: (monsterId: string) => void;
  completeQuest: (questId: string) => void;
  healPlayer: () => void;
  levelUp: () => void;
};
```

React вызывает `gameApi.attackTarget()`. Игра обновляет стор: HP, цель, лог боя.

**Важно:** правила кадра — в [performance.md](./performance.md). Коротко: позицию не писать в React/Zustand каждый кадр; один Engine; без дубля в StrictMode.

## 8. Тестирование без чтения кода

Раз код не читается, нужен встроенный тестовый режим.

### Панель GM (консоль Периметра)

Heal, Full stamina, Level Up, +1000 Exp, Teleport to NPC, Teleport to Monster, Spawn Hryak, Kill Target, Complete Quest, Give Medkit, Reset Save, Toggle Auto, Show FPS.

### Игровой лог

```text
[Система] Вылазка начата.
[Бой] Вы атаковали хряка.
[Бой] Хряк получил 12 урона.
[Бой] Хряк пал.
[Опыт] Получено 20 опыта.
[Заказ] Хряки у депо: 1/3.
```

### Кнопка AUTO TEST

Сама: подходит к Кефиру → берёт заказ → идёт к хрякам → бьёт → сдаёт → получает награду → пишет результат.

Если это работает — ядро игры живое.

После каждой фичи:

1. `npm run build` без ошибок TypeScript.
2. FPS в GM: побегать с камерой и Авто, кадры не должны просесть.
3. Ручной прогон по `PLAYTEST.md`.
4. Коммит, если фича работает и FPS живой.

Не просить «сделай AAA-зону как в большой игре». Просить **одну конкретную фичу**.

## 9. Визуальный стиль

Без дорогих ассетов, атмосфера Периметра:

- густой туман;
- больной зеленовато-серый свет;
- пасмурное небо, не закатная открытка;
- бетон, ржавчина, грязная олива;
- UI: олива, ржавчина, тусклый жёлтый, шум как у старого КПК;
- столбы и трубы из цилиндров;
- «руины» и «депо» из кубов;
- редкие светящиеся сферы как слабые аномалии (декор, не физика).

На этапе вайбкодинга как можно дольше сидеть на примитивах Babylon:

- игрок — оливковая капсула;
- мутант — ржаво-красная капсула или бокс;
- NPC — грязно-жёлтый цилиндр;
- маркер заказа — тускло-жёлтая сфера или конус.

Почему: меньше проблем с путями, форматами и выдуманными файлами.

Позже, когда примитивы работают: готовые low-poly паки (Kenney, Poly Pizza, Quaternius и т.д.), не «сгенерированная 3D-модель из картинки». Текстуры — по спеке, не сырой вывод генератора. Откуда графика и что генерация не умеет — в [assets.md](./assets.md).

**Уже в клиенте:** туман EXP2, hemi + один directional, плоскость без тайла, кубы/трубы и Kenney на Насыпи. **Ещё нет:** пасмурный купол (небо = `clearColor`), тайл земли, сферы-аномалии, столкновения со статикой. Это фазы 13–15 в [plan.md](./plan.md): купол и земля, декор, AABB (не Havok). Тени и постпроцесс не входят.

Только после того, как одиночная вылазка уже интересная.

## 11. Критерий успеха

Прототип минимально успешен, если как игрок можно:

1. Зайти в Периметр и увидеть шаталкера.
2. Побежать и покрутить камеру.
3. Подойти к Кефиру, открыть диалог, взять заказ.
4. Видеть заказ в трекере.
5. Найти хряков, выбрать цель, атаковать, увидеть урон.
6. Убить хряка, получить опыт, собрать прогресс заказа.
7. Вернуться к Кефиру, сдать заказ, получить награду.
8. Использовать аптечку.
9. Видеть рацию, где боты создают видимость общего Периметра.

Минимальное подобие — это цикл:

```text
Взять заказ
→ автоматически идти
→ автоматически бить мутантов
→ получить опыт
→ повысить ранг
→ сдать заказ
→ получить предмет
→ стать крепче
→ идти к следующему заказу
```

Если цикл есть и он пахнет туманом и рацией — это уже нужная атмосфера.

### Первый «вау»-набор

1. Шаталкер-капсула, третье лицо, клик-мув.
2. 3 хряка, 1 барыга, заказ «убить 3».
3. Таб-таргет, атака по `1`, цифры урона.
4. Опыт, ранг, трекер, диалог, награда.
5. Фейковая рация, 5 фейковых шаталкеров.
6. Кнопка Авто, миникарта.

## 12. Пошаговый план промптов

Порядок работ с нуля — в [plan.md](./plan.md). Не просить сразу весь Периметр. Слои по одному. После каждого слоя — обновить `PLAYTEST.md`, не ломать существующий код.

Тексты промптов — в [prompts.md](./prompts.md).

1. **Движение и камера** — WASD, мышь вокруг игрока, клик-мув, индикатор точки назначения.
2. **Мутанты и цель** — 5 хряков, Tab, TargetFrame.
3. **Бой** — таб-таргет, кулдаун 1 с, урон `attack ± 2`, всплывающий урон, ответ мутанта, лог боя.
4. **Опыт и ранг** — level up: +20 maxHp, +10 maxMp, +2 attack, полный хил, тост «Ранг повышен», GM `+1000 exp`.
5. **NPC и диалог** — Барыга Кефир, `F`, принять заказ / закрыть.
6. **Заказы** — `kill_hryaks_3`, трекер 0/3, «можно сдать» на 3/3.
7. **Сдача заказа** — кнопка награды, опыт + предмет, GM Complete current quest.
8. **Инвентарь** — `I`, малая аптечка (+30 HP), мясо хряка, количество.
9. **Миникарта** — 2D canvas, 5–10 FPS, игрок / мутанты / NPC / цель заказа.
10. **Фейковые шаталкеры** — 6 ботов, позывные, цвета, патруль, рация, иногда бьют хряков.
11. **Рация** — система / Периметр / бой, ввод игрока, ответы ботов, системные события.
12. **Авто-режим** — заказ → хряк → атака → Кефир → сдать → повтор; лог авто; GM teleport to quest target.

Стартовый промпт и детальные тексты шагов 1–12 — в [prompts.md](./prompts.md). Фазы 0 и 7–12 (репо, сейв, сервер, прод) и 13–15 (небо, декор, коллизия) — в [plan.md](./plan.md).

> FPS важнее фич.  
> Не делай сразу настоящий онлайн.  
> Сделай одиночный прототип Ш.А.Т.А.Л.К.Е.Р. с фейковым Периметром.  
> Добавь заказы, автобой, рацию с ботами, миникарту и ранг.  
> Тестируй через GM-панель, FPS и авто-тесты, а не через чтение кода.

Это самый реалистичный способ получить играбельную вылазку вайбкодингом в Cursor и не утонуть в сложности.
