# Производительность

Главная задача клиента: **стабильные кадры**. Атмосфера, фичи и «онлайн» не важнее FPS.

Ориентир: **60 FPS** на встроенной графике (старый ноутбук). Если фича роняет кадры — её нет, пока не починят. В GM всегда виден FPS.

Подробности мира — в [idea.md](./idea.md).

---

## 1. Разделение нагрузки

| Слой | Частота | Что туда нельзя |
| --- | --- | --- |
| Babylon `runRenderLoop` | каждый кадр | React setState, Zustand для xyz, аллокации, `console.log` |
| Игровые системы | каждый кадр, дёшево | создание мешей, материалов, текстур |
| Zustand / React HUD | по событию или 5–10 раз в секунду | позиция игрока, все мобы, каждый тик HP если не менялся |
| Миникарта | 5–10 FPS | рендер 3D-сцены во второй камере каждый кадр |
| Сейв на сервер | 5–10 с и на выход | позиция каждый кадр по HTTP/WS |

3D живёт в движке. React рисует КПК. Zustand — редкие факты (HP, цель, заказ, окна).

---

## 2. Babylon

- Один `Engine`, одна `Scene`, один canvas. Создать один раз, `dispose` при размонтировании.
- Не плодить движок в React StrictMode (ref / singleton).
- Внешние модели — только файлы, которые уже лежат в `/public/assets`. Статику после загрузки не двигать: `freezeWorldMatrix`, `isPickable = false`. Если пак роняет FPS — вернуть примитивы.
- Нет плагинной физики (Havok и т.п.) и нет ragdoll. Фаза 15 — только кинематические AABB/цилиндры из `src/data`, без cooking меша каждый кадр.
- Нет теней, bloom, SSAO, SSR, нескольких камер для постпроцесса.
- Свет: максимум hemispheric + один directional. Без кучи point light «фонариков», пока FPS не запасён. Сферы-аномалии (фаза 14) — emissive, не point light.
- Туман — можно и уже есть. Небо фазы 13 — градиентный купол или файл из `/public/assets`, не HDRI 2K+. Купол не pickable.
- Статичное окружение (кубы депо, трубы): не двигать, не пересоздавать. По возможности `freezeWorldMatrix`.
- Смерть хряка: `dispose` меша и материалов, которые больше не шарятся. Не прятать сто мёртвых тел.
- Не создавать `StandardMaterial` / динамические текстуры в цикле кадра.
- Цифры урона: не новая DynamicTexture на каждый удар. Пул короткоживущих мешей или DOM, лимит на экране (например 12).
- Имена над головой: не обновлять текст, если строка не изменилась.
- `hardwareScalingLevel` / снижение разрешения — допустимый рычаг в GM, если FPS < 50.

## 3. React и Zustand

- Подписка только на нужные поля (`hp`, не весь стор).
- Позицию в стор писать троттлингом (миникарта, сейв), не 60 раз в секунду.
- HP/MP/цель — когда значение реально сменилось.
- Не хранить в React меши, камеру, engine.
- Без Tailwind, CSS-in-JS, UI-китов: меньше рантайма на главном потоке.
- КПК: простые div, без тяжёлых анимаций и blur на весь экран.

---

## 4. Системы и боты

- 1 игрок, порядка 5 мутантов (хряки + рыскари), 6 фейковых шаталкеров — не «сотня NPC для атмосферы».
- ИИ ботов и автопуть: не raycast на всех каждый кадр. Реже или по очереди.
- Автобой идёт по прямой, без navmesh в MVP. После фазы 15 — скольжение по AABB, не поиск пути.
- Чат ботов — таймеры, не проверка фраз в render loop.
- Клики по земле: один raycast по событию мыши, не каждый кадр. Купол неба не pickable.
- Урон аномалий и радиация — тот же тик, что миникарта (5–10 Гц), не Zustand каждый кадр.

---

## 5. Сеть (когда появится)

- Не слать и не принимать позиции 20 раз в секунду, пока не попросили комнату.
- Сейв — снимок раз в несколько секунд.
- Рация — события, не тик.

---

## 6. Как проверять, не читая код

После каждой фичи:

1. Включить FPS в GM.
2. Побегать, покрутить камеру, включить Авто, постоять у пяти хряков и ботов.
3. Кадры не должны проседать «в пол» относительно пустой сцены.
4. Нет утечки: поубивать хряков пачкой, FPS не должен деградировать со временем.

Если после фичи FPS хуже — откатить или упростить, не оставлять «потом оптимизируем».
